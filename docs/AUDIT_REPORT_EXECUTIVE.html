4 Business Logics Applied — Part 1: Exams & Grading
Verify Your Business Rules
🎯
Special Section for CEO Verification
Below is a plain-English translation of the exact grading, testing, and scoring rules coded into your website. Please review each rule: if any rule does not match your business model, tell us and we will adjust the code to your preference.
1. Exam Passing Score: 84% Default
Needs CEO Confirmation
How it works right now: The code says: passed = scorePercent >= (test.pass_mark || 84).
If an administrator creates a test and forgets to fill in the passing mark, the system automatically demands 84% to pass!
Question for You: Is 84% your intended passing standard for KVJ Analytics certifications? In most professional analytics academies, the passing grade is usually 60%, 70%, or 75%. If 84% is too harsh, we can change the default to your preferred percentage.
2. Exam Attempt Limits: Currently Unrestricted
Missing Server Enforcement
How it works right now: The database has an attempts_allowed setting (e.g. 1, 2, or 3 attempts). However, the grading server never checks it upon submission. A student can retake the exact same mock test 50 times in a row.
Question for You: Do you want students to have unlimited practice attempts on mock tests, or should the system block them once they reach the limit (e.g. max 3 attempts per student)?
3. Negative Marking: Configured in Database but Inactive in Code
Inactive Feature
How it works right now: The database has a negative_marking field and instructions tell students about negative marks. But the server grading code calculates: earned = isCorrect ? marks : 0. Wrong answers give 0 points; they never subtract points.
Question for You: Do you want negative marking enabled (e.g. -0.25 marks for wrong answers to discourage guessing), or do you prefer no negative penalty (0 marks for wrong)?
4. Scoring Methodology per Question Type
Granular Grading System
Here is how each of your 10 question formats is graded:
  • Single Choice & True/False: Full marks if correct; 0 if wrong.
  • Multiple Choice (Checkboxes): All-or-Nothing! If a question has 3 correct answers and the student picks 2 correct and 0 wrong, they receive 0 marks. No partial credit is given.
  • Drag-to-Table & Pivot Tables: Partial Credit! 1 mark for each correctly placed slot. (e.g., 4 out of 5 correct = 4 marks).
  • Drag & Drop Pairs: 1 mark per correct match.
  • Fill-in-the-Blanks: 1 mark per blank, case-insensitive (e.g. "sum" matches "SUM").
  • Code Questions: Python/JavaScript/SQL code is evaluated against test cases. Partial credit is given based on how many tests pass.
Question for You: For Multiple Choice questions, should students get partial credit for selecting some of the correct options, or keep it strict all-or-nothing?
5 Business Logics Applied — Part 2: Payments, Codes & Certificates
Commercial & Administrative Rules
5. Razorpay Pricing & 18% GST Tax Invoicing
Tax Compliance Insight
How it works right now: All course prices listed on your website (e.g. ₹4,999) are treated as 18% GST Tax-Inclusive.
The system automatically computes:
• Taxable Base = Total Amount ÷ 1.18
• CGST (9%) = Taxable Base × 0.09
• SGST (9%) = Taxable Base × 0.09
An automated tax invoice (e.g. INV-784920) is emailed to the student via Resend using your GSTIN (32BIDPK3118B1Z2).
Crucial Tax Question for You: Your company is registered in Kerala (State 32). Under Indian GST law, when a student from another state (e.g. Tamil Nadu, Karnataka, Maharashtra) purchases a course, the invoice must reflect 18% IGST, not CGST + SGST. Currently, your system applies CGST + SGST to everyone in India. Would you like us to add state detection so out-of-state buyers receive proper IGST invoices?
6. Free Course Enrollment Records as "Paid"
Logical Database Bug
How it works right now: When a student signs up for a 100% free course via /api/enroll/free, the code writes to your database: enrollment_method: "paid".
Impact: In your Admin reports, free enrollments and paying customers get mixed together, making it impossible to see your true commercial revenue and conversion rate cleanly.
7. Access Codes & College Batch Codes (TOTP)
Sophisticated Logic
Your unlock system has two powerful mechanisms:
1. Static Promo Codes: Gated by seat limits (e.g. first 100 students), expiration dates, and college email domain restrictions (e.g. only @srm.edu.in).
2. Rotating 6-Digit Batch Codes: Uses time-based security (TOTP) where a 6-digit code changes every 30 seconds on the projector screen for college classroom batches so students cannot share codes with absent peers.
Safety Note: Once redeemed, the student is marked as enrolled and cannot redeem the same code twice. (This logic is sound and works well).
8. Certificate Issuance & Verification
Manual vs Automated
How it works right now: Certificates are 100% manual. When a student completes a course, nothing happens automatically. An admin must manually log into /admin/certificates, type the student's email, and click "Issue". Each certificate gets a unique 10-digit code (e.g. KVJ-2026-A1B2C3) and can be verified publicly at /certificates/verify/[code].
Question for You: Do you want certificates to be automatically issued when a student finishes 100% of lessons and passes all exams, or do you prefer to keep manual admin approval before any certificate is awarded?
6 Architecture, Mobile & Digital Marketing Strategy
Cross-Discipline Recommendations
🏛️ Architecture & Security
1. Single Database Schema: Combine the 19 fragmented SQL scripts into one clean migration file. This ensures you can clone or restore your website in 5 minutes if needed.

2. Security Gatekeeper: Currently, payment requests trust the phone to declare who the user is. We will lock this so the server strictly identifies students from their encrypted login cookie.

3. Remove Build Error Suppression: next.config.ts currently has ignoreBuildErrors: true. We verified your code has 0 errors—this flag can now be safely turned off to keep code quality high.
📱 Mobile App & PWA
1. Progressive Web App (PWA): Add a manifest.json so when students open KVJ Analytics on Safari or Chrome mobile, a banner prompts: "Install KVJ App on Home Screen" with your brand icon.

2. Touch-Friendly Exam Mode: Dragging tiny table items with a thumb on a smartphone can be frustrating. Add a "Tap Option A, then Tap Target Slot" mode on mobile devices.

3. Full-Screen Study Mode: On mobile, auto-collapse the top navigation bar when viewing lesson slides to give students 100% screen real estate for learning.
